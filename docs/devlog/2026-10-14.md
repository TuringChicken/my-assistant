## Decisions
- Stream every model turn, not just the final answer — a single code path for
  tool and non-tool turns.
- Thinking text (if the model emits it) is kept in history but not displayed.
- Gradio over Streamlit: Streamlit re-runs the script per interaction, which
  conflicts with long-lived MCP sessions.
- Gradio handlers run on Gradio's own thread/event loop, but MCP sessions are
  bound to the main loop. Each turn is submitted to the main loop via
  `run_coroutine_threadsafe`; tokens/events come back through a queue.

## Problems / Notes
- The 2026-10-08 note "tool calling is incompatible with streaming" is outdated.
  Current Ollama streams tool calls; each tool call arrives whole in a single
  chunk, so the client only needs to collect them, not reassemble fragments.
- Any preamble text the model emits before a tool call ("Let me calculate…") is
  now shown live, ahead of the tool-event line.
- When CLI output is piped/redirected on Windows, Python uses the GBK codepage and
  crashes on emoji (`UnicodeEncodeError`). Interactive terminals are fine; set
  `PYTHONIOENCODING=utf-8` when piping.
- Stopping a turn mid-stream (closing the tab) can leave an incomplete turn in
  that session's history; "New chat" clears it.
